# نسخهٔ ۲۰ — گزارش ممیزی و فرم تداوم

مبنای این نسخه، ZIP نسخهٔ ۱۹ ارسالی کاربر است. پیش از اعمال تغییرات، ساخت منبع آن بایت‌به‌بایت با HTML ارسالی مطابقت داده شد.

## گزارش ممیزی

- شرح یافته فقط بر مبنای مقادیر پرشده ساخته می‌شود. برچسب فیلدهای خالی و عبارت‌های جایگزین «ثبت نشده» حذف می‌شوند. صفر، وضعیت «اجرا نشده» و مقدار معتبر «خیر» خالی محسوب نمی‌شوند.
- اطلاعات الزامات و ۹۳ کنترل حفظ می‌شود؛ موارد فاقد یافته از گزارش استاندارد حذف نمی‌شوند و پوشش ثبت وضعیت صریح باقی می‌ماند.
- ستون یافتهٔ ممیزی Word با رنگ اصلی همان وضعیت در نرم‌افزار رنگ می‌گیرد؛ متن با کنتراست مناسب روی زمینه قرار دارد. وضعیت‌های انطباق، جزیی، کلی، مشاهده، توصیه و نقطه قوت مستقل‌اند.
- خروجی Word، Excel، HTML و چاپ/PDF این فرم، فقط ممیزی الزامات و Annex A است. اطلاعات ریسک، BCMS، RTP و پروژه‌های اقدامات اصلاحی به آن ضمیمه نمی‌شوند. گزارش مستقل اقدامات اصلاحی همچنان از بخش خودش قابل استفاده است.
- «دریافت گزارش HTML» یک فایل مستقل آفلاین شامل اطلاعات عمومی ممیزی، کارت‌های خلاصه، نمودارهای انطباق و حوزه‌ها، رادارهای پیاده‌سازی، منوی داخلی، جستجو و فیلتر تولید می‌کند. فونت‌ها و نمودارها داخلی‌اند؛ CDN، سرور و اینترنت لازم نیست.
- وضعیت انتخاب‌نشده با وضعیت عدم انطباق یکی فرض نمی‌شود؛ موارد غیرقابل اعمال از مخرج نمودارها حذف می‌شوند. شاخص پیاده‌سازی به‌صورت جدا از وضعیت انطباق معرفی می‌شود.

## BCMS

فرم در ۹ تب قرار دارد: اطلاعات اصلی؛ اثر وقفه و MTPD؛ اهداف و قابلیت بازیابی؛ طرح، مستندات و روش کار؛ ماتریس ارتباطات و وظایف؛ منابع و دارایی‌ها؛ سناریو، پشتیبان و مراحل بازیابی؛ آزمون؛ نمای گرافیکی.

کلیدهای قدیمی، واحد زمان ذخیره‌شده (دقیقه)، شناسه‌ها، قالب نسخهٔ ۲ مخزن BCMS و محاسبات MTPD/RPO/RTO/MBCO/WRT تغییر نکرده‌اند. جابه‌جایی تب، داده را ذخیره یا تبدیل نمی‌کند. فیلدها هنگام جابه‌جایی نصب می‌مانند تا انتخاب واحد کاربر از بین نرود.

صرفاً برای اطلاعات جدیدی که کاربر ثبت می‌کند، چهار ویژگی اختیاری داخل همان رکورد افزوده می‌شوند؛ رکورد قدیمی نیازی به مهاجرت یا داشتن این ویژگی‌ها ندارد:

- `emergencyContacts`: ردیف‌های دارای `id`, `name`, `contactMethod`, `contactNumber`, `role`, `authentication`, `responsibilities`؛ شماره تماس متن است تا صفر آغازین، + و داخلی حفظ شود.
- `planResources`: ردیف‌های دارای `id`, `name`, `type`, `quantity`, `location`, `owner`, `notes`؛ مقدار می‌تواند با واحد نوشته شود.
- `planDocuments`: ارجاع مستندات طرح.
- `operatingProcedure`: روش کار و دستورالعمل.

این داده‌ها از ماژول ریسک دریافت نمی‌شوند. فیلدهای جدید در همان پشتیبان پروژه، با همان قالب، نگهداری و بازیابی می‌شوند. کلیدهای ذخیره‌سازی جدیدی برای سازمان یا پروژه ایجاد نشده و ساختارهای قدیمی جایگزین نشده‌اند.

نمای گرافیکی آخرین تب است. کارت‌های RPO، RTO، MBCO، MTPD و KDS مقدار همان طرح را نشان می‌دهند؛ انتخاب هدف/قابلیت فعلی/آزمون به مقدار مربوط تغییر می‌کند. مقدار نامعلوم حدس زده نمی‌شود. موارد نیازمند بررسی زیر نمودار قرار دارند. کنترل با ماوس، صفحه‌کلید، تب قبلی/بعدی و موبایل پشتیبانی می‌شود.

## اجرا و انتقال

ZIP را استخراج و `START_HERE.html` یا `Didban_Amniat_Offline.html` را باز کنید. Source فقط برای توسعه است؛ اجرای آن برای استفاده لازم نیست. قبل از انتقال به پوشه یا رایانه دیگر، JSON پروژه را از پشتیبانی بگیرید. برای دریافت‌کننده جدید، HTML خام و JSON همان پروژه را ارسال کنید.

## اعتبارسنجی

آزمون‌های محاسبات، تقویم، منطق انطباق، رادار، اقدامات اصلاحی، RTP و گزارش‌های قبلی اجرا شدند. آزمون جدید، فیلد خالی، صفر و خیر، حفظ داده‌های نسخهٔ ۱۹، تب‌ها، کارت‌های هدف/فعلی/آزمون، JSON، صفحه‌کلید و موبایل را بررسی می‌کند. فایل Word با python-docx و XML parser و Excel با openpyxl مستقل از تولیدکننده بازخوانی شدند. HTML گزارش، جستجو، فیلتر، نمودار، محتوای متنی امن و اجرای بدون درخواست خارجی بررسی شده است.

آزمون مرورگری قدیمی اقدامات اصلاحی با انتظار جدید محدودهٔ گزارش ممیزی تطبیق داده شد: گزارش Word اقدامات اصلاحی از همان بخش خودش آزمایش می‌شود و انتظار ضمیمه‌شدن آن به Excel ممیزی عمداً وجود ندارد. منطق و داده‌های همان بخش تغییری نکرده‌اند.
